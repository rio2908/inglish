# Архитектура EnglishCraft

Поведение определяется [спецификацией](GAME_DESIGN.md). Этот документ описывает текущую реализацию, а не разрешает менять правила.

## Карта модулей

| Модуль | Ответственность |
| --- | --- |
| `main.py` | `GameApp`, экраны, события Pygame, координаты, связывание модели и отрисовки |
| `game_logic.py` | Новое состояние, нормализация, уроки, знание слов, стадии роста, уход, сад, события взросления |
| `words.py`, `curricula.py` | Шесть проверяемых наборов, стабильные English-ID, произношение и перевод |
| `grammar.py` | Однословные правила, примеры и варианты контекстных вопросов |
| `learning_stats.py` | Попытки, очередь ошибок, выученный порядок, короткие проверки по виду и циклу |
| `vocabulary.py` | Read-only выборка выученных слов текущего игрока, поиск и фильтры без начисления прогресса |
| `zoo.py` | Последовательное открытие, итоговые тесты, повторное выращивание, ожидающий питомец |
| `player_profiles.py` | `PlayerStore`: регистрация, выбор, запись конкретного игрока, миграция, план безопасного импорта |
| `game_storage.py` | Низкоуровневый JSON/atomic replace/localStorage, переносимые копии, совместимость старого формата |
| `game_backup.py` | Системный Android picker, browser download/upload, desktop dialog; результат обрабатывается в `poll()` |
| `sprites.py` | Загрузка исходных спрайтов сниффера, выбор вида, кэш масштабированных изображений |
| `creature_sprites.py` | Пиксельные стадии и кадры движения пяти новых видов |
| `word_pictures.py` | Смысловые ассоциации слов, кэш рисунков, явное отсутствие рисунка для неподдержанного слова |
| `habitats.py` | Кэш основы биома, возрастные детали и лёгкая анимация |
| `pet_behavior.py` | Движение по возрасту, реакция на поглаживание, ограниченные частицы сердец |
| `pet_games.py` | Независимые от Pygame состояния четырёх мини-игр |
| `speech.py` | WAV, Android TTS в UI-потоке, Web Speech, Windows System.Speech, остановка и ошибки |
| `instructions.py` | Короткие страницы справки; возрастные числа берутся из `GROWTH_THRESHOLDS` |

Модель обучения/зоопарка/профилей не импортирует Pygame. Она тестируется без окна. `learning_stats.py` использует сведения зоопарка; запись статистики итогового теста в `zoo.py` делает отложенный импорт, чтобы не создавать цикл при загрузке модулей.

## Поток управления

```text
GameApp(profile_store=...) → выбор/регистрация игрока
    → PlayerStore.load_profile(id) → game + revision → normalize_game
    → activate_game → сброс transient-данных → restore_lesson
    → home / cards / review / final_test / growth

событие UI → функция модели → GameApp.persist()
    → PlayerStore.save_game(id, game, expected_revision=revision)
    → свежий документ игроков → замена только game выбранного id
    → write_save_document → atomic JSON / localStorage
```

`main()` остаётся асинхронным: события → озвучка → результат picker → отрисовка → `await asyncio.sleep(0)` → ограничение FPS. Новые состояния должны иметь явный вход, отрисовку, выход и обработку Escape.

## Экраны

- `login`, `register` — без выбранного игрока; можно открыть `help` и импорт.
- `home`, `profile`, `name` — текущий питомец, игрок и два независимых имени.
- `cards` — `intro → quiz → result`; очередь и позиция лежат в `game.lesson`.
- `review`, `final_test` — сохраняемые `quiz → feedback → summary`.
- `growth` — сохраняемое поздравление; подтверждение возвращает к результату того же урока.
- `feed`, `play`, `story`, `statistics` — вспомогательные экраны игрока.
- `zoo`, `resident`, `replay_confirm` — коллекция, посещение и подтверждение нового цикла.
- `import` — явное подтверждение назначения копии.
- `help` — страницы инструкции и возврат на исходный экран, включая регистрацию с незавершённым вводом.
- `dictionary` — личный словарик, возврат в сад/зоопарк/итоговый тест без изменения их состояния. Поле поиска использует отдельный режим текстового ввода.

На login/register нет активного `player_id`, поэтому `persist()` не записывает демонстрационный `new_game()`. После успешного выхода активный `game` заменяется пустым демонстрационным состоянием: справка на входе не показывает возраст/биом прежнего игрока. На входе в другого игрока останавливается звук, очищаются частицы, мини-игра, очередь, уведомления UI и затем восстанавливается только выбранный `game`.

## Документ игроков

Физическое имя сохраняется для совместимости: `sniffer_save.json`; browser key — `sniffer-garden-save-v1`.

```json
{
  "format": "englishcraft-players",
  "version": 2,
  "last_player": "stable-id",
  "profiles": {
    "stable-id": {"name": "Имя игрока", "revision": 0, "game": {"version": 1}}
  }
}
```

ID не зависит от имени и не используется как путь. Имена нормализуются отдельно, дубликаты определяются `casefold()`. `PlayerStore` перед записью перечитывает документ и заменяет только один профиль. `load_profile()` возвращает игру и её ревизию одним чтением; `GameApp` хранит собственный токен и передаёт его в `save_game`. Успешная запись увеличивает ревизию, устаревшая вызывает `StaleProfileError` без записи. Нельзя читать свежую ревизию и присваивать её старому `game` ради обхода конфликта. `replace=True` используется только подтверждённым восстановлением копии.

Документ игроков version 1 автоматически и атомарно мигрирует в version 2 с начальными ревизиями, без изменения ID, имён и игр. Старые клиенты, понимающие только v1, отказываются записывать v2: это защищает от оставшейся старой web-вкладки. Версии переносимых JSON-копий 1/2 не менялись. Это не протокол конкурентного облачного редактирования и не обещание автоматического слияния одновременной игры: активным должен оставаться один экземпляр UI.

Возврат фокуса проверяет актуальность выбранного профиля без изменения `game`. При несовпадении ревизий отображается отдельный экран с экспортом локальной копии и явной загрузкой свежего состояния. Экспорт использует проверенные при входе ID/имя из сессии и остаётся доступен даже при недоступном приватном хранилище.

Повреждённый/неизвестный документ не превращается в пустой при регистрации. Старая одиночная игра мигрирует в один профиль «Сохранённая игра» атомарной записью. Legacy `write_game` отказывается перезаписывать документ игроков одиночным состоянием.

## Состояние `game`

Канонические значения по умолчанию: `new_game()`. Все новые сохраняемые поля должны поддерживаться `normalize_game()` или специализированным нормализатором.

- `pet_name`, `session`, `correct_answers` — имя питомца, монотонный номер раунда и общая история правильных ответов. **`correct_answers` не определяет рост**.
- `cards[id] = {seen, correct_sessions}` — знание всех наборов; английский ID стабилен, два разных раунда означают mastery.
- `lesson = {queue, index, phase, mode, correct, answers}` либо `null` — продолжение карточек. Сохраняется до временного перехода к проверке/поздравлению.
- `word_stats`, `repeat_words`, `learned_order` — счётчики уроков/проверок, очередь ошибок и порядок изучения.
- `reviews`, `active_review` — история и незаконченная короткая проверка; ключ результата включает вид, цикл и рубеж. Старые записи без вида/цикла означают сниффера/нулевой цикл.
- `growth_notice = {species, cycle, before, after}` либо `null` — одно ещё не подтверждённое превращение; нормализатор отбрасывает чужой/устаревший контекст.
- `care`, `feedings`, `poop`, `last_food`, `garden_plants` — уход и постоянный сад. Значения ограничиваются моделью.
- `zoo` — активный вид, выращенные друзья, отдельные данные повторного цикла, итоговый тест, история, цикл и ожидающий питомец.

В `zoo.pet_cards` хранится прогресс текущего повторного выращивания. В обычном прохождении рост читается из `game.cards` своего набора. `zoo.exam` имеет 10 ID, список ответов и фазу; допуск вычисляется по реальным ответам, не по произвольному UI-флагу «passed».

`leave_cards()` сначала сохраняет снимок карточки, затем переводит UI в сад, не очищая `lesson` и не завершая раунд. `start_lesson()` сначала восстанавливает существующие урок/проверку/поздравление; новый `session` создаётся только для действительно нового урока. Это необходимо и для экспорта через меню профиля, иначе очередь исчезала ещё до создания JSON.

Повторный цикл хранит снимок `zoo.suspended` для ожидающего питомца: его вид/цикл, имя, уход, данные роста, итоговый тест и незакрытое поздравление. Вложенные повторные циклы не допускаются. После успешного завершения восстанавливается снимок, но сохраняются обновлённая коллекция, общая статистика и история тестов.

Нормализация `reviews` учитывает три контекста: текущий вид/цикл, ожидающий вид/цикл и ранее выращенные виды. Для ожидающего питомца допустимые рубежи определяются его собственным сохранённым прогрессом. Нельзя отбрасывать его результаты только потому, что он ещё не переселён в зоопарк и сейчас активно другое яйцо.

## Совместимость экспорта

- Envelope `sniffer-garden-profile`, version 1 — прежняя игра без владельца.
- Тот же format, version 2 — `player: {id, name}` + `game` выбранного игрока.
- `read_backup_bytes` оставлен для legacy-потребителей одного `game`; новый UI использует `read_player_backup_bytes` с владельцем.
- `ProfilePicker` принимает decoder, поэтому платформенный мост не решает правила назначения игрока.
- `PlayerStore.import_target/restore_backup` определяет создание/замену и запрещает замену существующего другого игрока.
- UI дополнительно запоминает владельца асинхронной операции: поздний callback после смены игрока не применяется к новому профилю.

Android-мост основан на том же подходе, что в MathCraft: `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT`, callback Activity и `ContentResolver.openFileDescriptor`. Для экспорта используется режим `wt`, а у seekable-дескриптора после записи вызывается `truncate()`: один `fdopen(..., "wb")` уже открытый файл не обрезает. Для pipe/потоковых документов seek/truncate не требуются. Дескриптор закрывается до сообщения об успехе.

`ProfilePicker.start()` возвращает признак принятия запроса, `busy` учитывает также ещё не обработанный результат. Владелец операции в `GameApp` меняется только после реально принятого запроса. Android callback принимается только для текущего `request_code` и непустого pending-состояния. Ошибка открытия browser picker сбрасывает pending, позволяя повторить попытку.

## Отрисовка и transient-состояния

Холст фиксирован 1000×600, итоговое изображение масштабируется с сохранением пропорций. Клик и finger-координаты переводятся обратно в координаты холста. Существует защита от дублированного touch/mouse события.

Фоны кэшируются по виду/размеру/режиму игры, возрастные детали дорисовываются без отдельного полноэкранного кэша на каждую стадию. Спрайты кэшируются с учётом вида. `WordPictures` возвращает `None`, если осмысленного изображения нет.

Позиции питомца, фаза дыхания, частицы, открытая страница справки, фильтры/поиск словарика и незаконченный мини-игровой раунд не являются знаниями игрока и не записываются как прогресс. Словарик вычисляется из `game.cards`, а не из отдельной копии списка; при смене игрока его UI-состояние сбрасывается. Временной шаг движения ограничен, чтобы не симулировать часы отсутствия после возвращения. Общий UI-кэш картинок не содержит приватного прогресса и может использоваться разными игроками.

## Защита переходов урока

Обработчики карточек, коротких и итоговых проверок сверяют текущий экран и фазу: повторный «Дальше» не пропускает карточку, отложенный ответ после выхода не начисляет попытку. Набор кликабельных областей принадлежит отрисованному экрану и игроку; после действия следующий клик принимается только после перерисовки. Экран конфликта не обрабатывает скрытые области питомца и уборки.

Номер `session` при нормализации сверяется с сохранёнными положительными номерами ответов, в том числе повторного и ожидающего питомца. Утерянный/отставший счётчик восстанавливается; при незавершённом уроке выделяется свежий номер. Корректный счётчик не меняется. `record_answer` отклоняет раунд 0 и неизвестный ID до изменения статистики. Формат сохранения не изменён.

## Android-озвучка

TTS создаётся и вызывается в UI-потоке Android. Современный `speak` получает явные Java `String`/`CharSequence` и `Bundle`, без неоднозначного Python `str` + `None`. Если binding не поддержал этот overload, используется трёхаргументный вариант с `HashMap`. Локаль создаётся как `Locale("en", "US")`.

Поколения инициализации и произнесения не позволяют позднему callback/queued Runnable включить старый звук после `stop()` или `shutdown()`. Неуспешный уже созданный движок переинициализируется при следующем запросе; таймаут также допускает повтор. Успешное прослушивание очищает старую ошибку UI.

`Speech.error` — только короткое пользовательское сообщение. Техническая причина остаётся в `Speech.last_error` и logger `speech` (`Android TTS` в logcat), не внизу детской карточки и не в сохранении профиля. Реальную совместимость JNI/голосового движка нужно проверять на устройстве; строгие fake-интерфейсы в тестах не заменяют Android.

## Время жизни ресурсов

Android-listener инициализации TTS использует слабую ссылку на `Speech`: удерживаемый Java callback не удерживает весь Python-объект. `shutdown()` останавливает TTS/локальный звук, освобождает WAV-кэш, listener и локаль. `ProfilePicker.close()` отписывает callback Activity и очищает незавершённый payload/result. Главный цикл вызывает обе очистки перед `pygame.quit()`, в том числе при исключении во второй очистке.

Кэши графики живут вместе с `GameApp` и переиспользуются между игроками. При фиксированных размерах/наборах кадров они должны выходить на плато, а не расти с числом кадров. Данные изучения (`correct_sessions`, результаты проверок/повторов) — сохраняемая история, её рост при новых ответах не является утечкой transient-объектов. Не обрезайте её в рамках оптимизации памяти без отдельного согласования.
