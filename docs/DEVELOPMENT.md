# Разработка и проверка EnglishCraft

Сначала прочитайте [AGENTS.md](../AGENTS.md), [спецификацию](GAME_DESIGN.md) и [архитектуру](ARCHITECTURE.md).

## Окружения

- Desktop: Python 3.12 и зависимости `requirements.txt` (`pygame-ce`; обычный pygame также поддерживается).
- Web: `requirements-web.txt`, Pygbag, асинхронный игровой цикл.
- Android: Buildozer из Linux/WSL или ручной workflow `Build Android Debug APK`. Версии в `buildozer.spec` соответствуют выбранному работающему стеку MathCraft: Python 3.10.11/hostpython3 3.10.11, pygame, PyJNIus, SDL2, p4a v2024.01.21, NDK 25b, API 34, min API 24, arm64-v8a. CI host Python 3.11 и Java 17 — отдельные от Python внутри APK инструменты.

Не обновляйте этот стек попутно с игровым исправлением. Название приложения — EnglishCraft; Android package `org.game.sniffergarden` оставлен неизменным для обновлений поверх установки.

## Запуск

```powershell
python -m pip install -r requirements.txt
python main.py
```

```powershell
$env:PYTHONUTF8 = "1"
python -m pip install -r requirements-web.txt
python -m pygbag --ume_block 0 .
```

Для web-артефакта: `python -m pygbag --build --ume_block 0 .`. Для Android из Linux/WSL: `buildozer -v android debug`. В Actions после push workflow запускается вручную; APK находится в артефакте `EnglishCraft-Android-debug`.

## Минимальный набор проверок

PowerShell:

```powershell
python -m py_compile main.py game_logic.py game_storage.py game_backup.py player_profiles.py learning_stats.py vocabulary.py pet_behavior.py pet_games.py creature_sprites.py habitats.py curricula.py grammar.py instructions.py word_pictures.py sprites.py speech.py words.py zoo.py

```

`pyflakes` входит в web-зависимости; если его нет, установите инструмент отдельно/во временное окружение и честно сообщите, что именно проверили. Не меняйте глобальное окружение пользователя без необходимости.

Те же команды работают в Linux (без PowerShell-переменных). UI-тесты используют SDL dummy. Если pygame не установлен, UI-модули тестов пропускаются: это нужно указать, а не выдавать pure-only прогон за проверку всех экранов.

## Обязательные функциональные сценарии

### Любое изменение прогресса/сохранений

1. Два разных игрока: разные имена питомцев, знания, потребности, зоопарки и результаты.
2. Переключение A → B → A и новый запуск с явным выбором: нет утечки UI/звука/очереди, восстановлен нужный урок.
3. Миграция одиночного сохранения, пустые/повреждённые данные, неизвестные поля, ошибка записи.
4. Экспорт A, импорт при выбранном B: A/B не перезаписываются молча; новая копия создаёт отдельного игрока.
5. Legacy-копия без имени: регистрация владельца на входе или подтверждение замены только текущего.
6. Незаконченная проверка, итоговый тест и поздравление переживают reload без повторного учёта ответа.
7. Повторное выращивание сохраняет ожидающего питомца и возвращает его с прежним итоговым тестом; повтор не обходит порог 70%.
8. Словарик A не содержит чужих/невыученных слов; поиск, прослушивание и скрытие перевода не меняют знания, статистику и результат теста. Возврат к неудачной итоговой попытке не начинает её заново и не засчитывает сдачу.
9. Выход из урока в сад → меню профиля → экспорт → импорт в пустое/существующее хранилище → новый запуск: восстанавливаются не только счётчики, но и очередь, карточка, фаза, care, зоопарк, ожидающий питомец и его история проверок.
10. Два клиента одного игрока: старый снимок с 4 выученными словами не перезаписывает свежий с 8. Проверьте отдельные `PlayerStore`, два `GameApp` с общим store, возврат фокуса, конфликт/выгрузку локальной копии/явную загрузку свежего и миграцию документа игроков v1 → v2. Подтверждённый импорт более ранней копии остаётся отдельным разрешённым действием.

Целевые проверки Android-переноса (нативные Java-классы имитируются, JSON и файловые дескрипторы настоящие):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_android_profiles.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_game_backup.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_player_ui.py -v
```

`test_android_profiles.py` проверяет экспорт/импорт фаз урока, коротких и итоговых проверок, поздравления, повторного выращивания, пустую установку, уже существующего игрока, защиту соседнего профиля и legacy-копию без владельца. Отдельно проверяйте перезапись более длинного документа, не обрезающий файл провайдер, nonseekable-дескриптор, отмену/чужой callback и повторный запрос при занятом picker. Имитация моста не заменяет проверку системного диалога на настоящем Android.

`test_android_speech.py` проверяет строгие типы Java-аргументов, legacy fallback, понятную ошибку вместо traceback, повторную инициализацию неудачного движка и отмену queued-озвучки/позднего callback после остановки. Если ошибка осталась на устройстве, запросите точный текст/logcat (`Android TTS`); не объявляйте причиной отсутствие голоса без проверки статуса.

Используйте `TemporaryDirectory()` и `PlayerStore(temp_path)`. Создавайте UI как `GameApp(profile_store=store)`. Не патчите рабочие сохранения и не запускайте автоклики на настоящем профиле.

### Изменение баланса

`test_logic_flow.py` проходит все шесть существ через настоящие обработчики `GameApp`: 900 слов, 30 коротких проверок, итоговые тесты и дополнительное повторное выращивание первого питомца с возвратом ожидающего второго. Хранилище в этом длительном сценарии — in-memory реализация `PlayerStore`; реальные файлы/миграции проверяются отдельными storage/UI-тестами. Отдельно проверяйте повторные клики в одном кадре, старые callbacks после выхода и восстановление номера раунда из старой копии.

Проверьте границы 29/30, 59/60, 89/90, 119/120, 149/150; два правильных ответа в одном и разных раундах; ровно 6/10 и 7/10 в итоговом тесте. Зафиксируйте, какой запрос пользователя разрешает изменение спецификации.

### Изменение UI/графики

- Отрисуйте соответствующий экран через SDL dummy и посмотрите реальный скриншот, не только отсутствие исключения.
- Проверьте самые длинные слова/фразы, имена до 20 символов и кнопки в холсте 1000×600.
- Проверьте смысл картинки, прозрачность и отсутствие зависимости от emoji-шрифта.
- Для нового экрана: Escape, кнопка назад, мобильный touch, восстановление нужного родительского экрана, при необходимости клавиатура.
- Для справки: доступ с входа/регистрации и из сада, сохранение введённого имени при возврате, все страницы и края навигации.

На Windows для скриптов с русскими строками, передаваемых через pipeline, задайте UTF-8 (`$OutputEncoding = [System.Text.UTF8Encoding]::new()`, `python -X utf8 -`). Иначе скриншот может получить `???` вместо кириллицы. Временные изображения храните в одобренном каталоге OpenCode, а не коммитьте как пользовательские данные.

## Границы локальной проверки

Desktop/dummy не проверяет Android TTS, реальную экранную клавиатуру, document picker, подпись APK или голос браузера. После изменения этих частей требуется отдельная проверка на устройстве/в браузере. Не пишите «APK исправлен и проверен», если была только компиляция Python.

Debug-ключ в Actions кэшируется для обновлений, но кэш может быть утрачен. Перед полным удалением приложения нужна внешняя копия каждого игрока. Не добавляйте ключи или пароли в Git.

## Документация после каждого исправления

Обновляйте затронутые документы, справку `instructions.py` и `README.md` в той же задаче. Каждое исправление отмечайте в [CHANGELOG.md](CHANGELOG.md): что изменилось, какое требование защищает тест, какие проверки реально выполнены и что осталось проверить на устройстве.

Не ослабляйте тесты, чтобы новая ошибка «стала зелёной». При внутреннем исправлении без изменения UX отметьте защищённую инварианту в журнале, не переписывая всю спецификацию.
