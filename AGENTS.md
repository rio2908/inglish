# EnglishCraft: правила работы для агентов

Перед изменениями прочитайте:

1. [Спецификацию игры](docs/GAME_DESIGN.md) — согласованные требования и игровые инварианты.
2. [Архитектуру](docs/ARCHITECTURE.md) — модули, состояния и сохранения.
3. [Разработку и проверки](docs/DEVELOPMENT.md) — безопасный рабочий процесс.
4. [Журнал изменений](docs/CHANGELOG.md) — последние решения и проверенные ограничения.

`README.md` — инструкция для пользователя; `instructions.py` — короткая справка внутри игры.

## Что считается источником требований

- Явное новое указание пользователя может менять спецификацию; обновляйте код, тесты и документацию вместе.
- Без такого указания сохраняйте правила из `docs/GAME_DESIGN.md`. Не меняйте баланс ради удобства реализации.
- Код с ошибкой не отменяет требования спецификации. Исправляйте регрессию, а не подгоняйте под неё тесты.
- Если запрос неоднозначен и влияет на прогресс, сохранения, число слов или пороги открытия — уточните его.
- MathCraft служит ориентиром только в оговорённой пользователем части. Не переносите самовольно его баланс, предметы или механики. Соседний репозиторий не меняйте.

## Неизменяемые без согласования инварианты

- 6 существ строго по очереди: сниффер, аксолотль, лиса, пчела, черепаха, эллей.
- 6 разных наборов по 150 карточек, всего 900 уникальных английских идентификаторов; 10 глав по 15 карточек в наборе.
- Слово выучено после правильного ответа в **двух разных раундах**, не после двух нажатий подряд.
- Рост по выученным словам: яйцо 0–29, малыш 30–59, подросток 60–89, взрослый 90–119, финальная форма от 120. Старая схема «пять ответов до вылупления» больше не действует.
- Контрольные на 50/100/150 слов: по 20 вопросов. Для продолжения нужны минимум 14/20 и завершённая работа над ошибками; изученное не отнимается, оценка при исправлении не меняется.
- Следующее существо открывается только после всех 150 слов, контрольных и итогового теста **не ниже 70%** с исправлением ошибок. Объёмы итогового теста по видам: 50/60/70/80/90/100 слов. Ограничение проверяется моделью, не только кнопкой.
- Повторное выращивание не выдаёт следующее существо, не удаляет взрослого друга и восстанавливает ожидающего питомца.
- Все состояния принадлежат выбранному игроку. Нельзя сохранять игру без выбранного профиля, смешивать статистику детей или молча заменять чужой профиль импортом.
- Устаревший снимок не перезаписывает свежий: UI сохраняет с ревизией, загруженной вместе с его `game`. Нельзя обходить конфликт свежим токеном для старых данных или `replace=True` вне подтверждённого импорта.
- Идентификатор Android `org.game.sniffergarden`, имена существ, слова-ID и форматы сохранений нельзя переименовывать без миграции. Название интерфейса — **EnglishCraft**.

## Правила реализации

- Игровые правила держите в `game_logic.py`, `learning_stats.py`, `zoo.py`; не дублируйте их в обработчиках UI.
- Доступ к пользовательским состояниям — через `PlayerStore` в `player_profiles.py`. Глобальные `load_game`/`write_game` в `game_storage.py` — совместимость с прежним одиночным форматом, не API активного игрока.
- Новые сохраняемые поля получают значения по умолчанию и нормализуются. Проверьте старые файлы и экспорт/импорт.
- При смене игрока сначала сохраните старого; сбрасывайте очереди UI, звук, частицы и мини-игры, затем восстановите только выбранного.
- Цикл остаётся `async`, с `await asyncio.sleep(0)` каждый кадр для Pygbag. Не добавляйте блокирующие задержки или сетевую загрузку в цикл.
- Сохраняйте разрешение 1000×600, landscape и крупные телефонные кнопки. Для нового экрана добавляйте отрисовку, обработку событий, выход и восстановление состояния.
- Иконки не зависят от эмодзи шрифта телефона. Не показывайте случайную картинку вместо значения слова.
- Правило карточки объясняет **только текущее слово**. Например, на карточке `is` не нужно объяснять `am` и `are`.
- Личный словарик — read-only представление выученного: просмотр/поиск/озвучка не начисляют ответы, не меняют очередь ошибок и не обходят итоговый тест.
- Не меняйте работающий Android-стек, подпись или пакет без отдельной причины и согласования. Локальный smoke-тест не доказывает работоспособность APK.

## Обязательный процесс после КАЖДОГО исправления

1. Проверьте `git status --short`; сохраняйте чужие изменения. Не коммитьте без запроса пользователя.
2. Определите затрагиваемые требования и сохранённые поля.
3. Измените код и добавьте регрессионный тест. При согласованном изменении правил обновите ожидаемые значения в тестах, не ослабляя проверки.
4. **Актуализируйте документацию в той же задаче:**
   - правила/пороги/UX → `docs/GAME_DESIGN.md`, `README.md`, при необходимости `instructions.py`;
   - модули/состояния/схема данных → `docs/ARCHITECTURE.md`;
   - запуск/инструменты/CI → `docs/DEVELOPMENT.md`;
   - любое исправление → запись в `docs/CHANGELOG.md` с причиной, результатом и проверками.
   - если поведение не менялось, достаточно записи в журнале о защищённой инварианте; не вносите бессмысленные изменения в остальные документы.
5. Выполните проверки из `docs/DEVELOPMENT.md`. Для UI проверьте реальный экран/скриншот; для сохранений — запись, перезапуск и миграцию в временном каталоге.
6. В итоговом сообщении укажите результат и границы проверки. Не называйте Android или браузер проверенными, если запускали только desktop/dummy.

## Безопасность пользовательской работы

- Не удаляйте и не перезаписывайте настоящие `sniffer_save.json` и `.tmp` во время тестов.
- Для тестов используйте `TemporaryDirectory` и `GameApp(profile_store=...)`; не запускайте автоматические сценарии на реальном хранилище.
- Не добавляйте в Git сохранения, резервные копии детей, debug/release-ключи, `build/`, `bin/`, `.buildozer/`, `__pycache__/` или временные скриншоты.
- Не используйте `git reset --hard`, `git checkout --` и широкое удаление для «очистки» проекта.
- Предпочитайте небольшие целевые изменения; не форматируйте весь `main.py` ради локальной правки.
